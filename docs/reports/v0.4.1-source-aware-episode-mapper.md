# Отчёт: Source-aware Episode Mapper v0.4.1

## Результат

Исправлено универсальное сопоставление аниме и номеров эпизодов без изменения Playback Controller и без масштабного рефакторинга. Плагин теперь получает проверенный TMDB TV ID из build-time mapping и переводит `source + season + episode` в абсолютный номер только по явному диапазону для конкретного аниме и адаптера.

Исходная диагностика Bleach показывала 408 классификаций, 372 строки, 7 распознанных номеров и шаблон `online_mod S1 E366`. Регресс-тест воспроизводит 372 структурированные строки: `S1 E1–366` и `S2 E1–6`. Все 372 получают однозначные абсолютные номера; значения за пределами проверенных диапазонов остаются `unknown`.

## Причина дефекта

Runtime v0.4.0 считал любое структурированное значение с сезоном допустимым только при наличии общего `seasonOffsets`. В bundle такое правило было добавлено лишь для One Piece S1. Поэтому Online_Mod передавал корректное `S1 E366`, но mapper отклонял его ещё до классификации Bleach.

Общий offset не решает задачу:

- Bleach: TMDB S1 содержит E1–366, а S2 начинает нумерацию заново с E1;
- One Piece: TMDB S2 содержит номера E62–77, то есть продолжает сквозную нумерацию;
- Naruto: TMDB S2 начинается с E53;
- Naruto Shippuden: TMDB S20 начинается с E414;
- BWA и другие источники могут передавать другую систему, поэтому их сезонные номера нельзя автоматически считать TMDB-номерами.

## Реализованное решение

### Build-time mapping

Добавлен файл `data/mappings/tmdb-tv.v1.json`. Builder читает его во время сборки, проверяет диапазоны и переносит их в title shard. Версия mapping входит в новый `buildId`, поэтому прежний валидный кэш не маскирует обновление.

| Аниме | TMDB TV | Каталог | Проверенные Online_Mod диапазоны |
|---|---:|---:|---|
| Bleach | 30984 | 408 | S1 E1–366 → 1–366; S2 E1–42 → 367–408 |
| One Piece | 37854 | 1173 | S1–S22; TMDB episode уже сквозной внутри каждого диапазона |
| Naruto | 46260 | 220 | S1 E1–52; S2 E53–104; S3 E105–158; S4 E159–220 |
| Naruto Shippuden | 31910 | 500 | S1–S20; последний диапазон S20 E414–500 |

Основной внешний источник mapping — AniBridge `mappings.edits.yaml`, закреплённый на revision `b9e7e129b21db37e0279c6458ac7d191f4ec1663` (MIT). Bleach TMDB ID и фактическое поведение Online_Mod `S1 E366` дополнительно подтверждены предоставленной диагностикой LG webOS. Классификация эпизодов остаётся из закреплённого SkipTheFiller snapshot `a7b28ff590b70652843125b77b9a80f334d2c3ca` (CC BY 4.0).

### Source-aware mapper

Перехват шаблонов записывает нормализованный adapter id:

| Шаблон Lampa | Adapter id | Правило v0.4.1 |
|---|---|---|
| `online_mod` | `online_mod` | Явные TMDB-диапазоны из shard |
| `lampac_prestige_full` | `bwa` | Только `absolute_episode`; сезонное значение → `unknown` |
| `online` | `lampa_online` | Только `absolute_episode`; сезонное значение → `unknown` |
| torrent event | `torrent` | Явный absolute или прежний однозначный filename parser |

Приоритет mapper:

1. Валидный `absolute_episode`.
2. Структурированный `season + episode` при наличии правила для точного adapter id и title shard.
3. Legacy `seasonOffsets` только для пользовательского guide без adapter id.
4. Однозначный номер из строки без сезона.
5. В остальных случаях `unknown`.

Неявное правило One Piece `seasonOffsets: {"1": 0}` удалено. Перекрывающиеся диапазоны, неизвестный slug, выход за длину классификации, неподдерживаемая система или неподтверждённый источник останавливают сборку либо возвращают `unknown`.

### Диагностика

В окно диагностики добавлены:

- `Неизвестных соответствий`;
- пример вида `online_mod S1 E366 → 366` или `bwa S1 E366 → unknown`.

Это позволяет отличить отсутствие классификации от сознательного fail-closed отказа mapper.

## Тесты

Автоматически проверяются:

- Bleach: 372 строки исходного сценария, границы S1/S2 и отказ для S2E43;
- One Piece: S2E62 → 62 и отказ для неверного S2E1;
- Naruto: S2E53 → 53 и отказ для S2E1;
- Naruto Shippuden: S20E414 → 414 и отказ для S20E1;
- BWA: сезонное значение без правила → `unknown`, явный `absolute_episode` принимается;
- неизвестный adapter id → `unknown`;
- перенос adapter id из шаблонов Online_Mod и BWA;
- отклонение mapping с пересечением диапазонов, неизвестным slug или выходом за границы каталога;
- SHA-256, cache/fallback, late-response protection и прежние parser/smoke тесты.

Команды проверки:

```bash
node --check lampa-anime-filler.js
node --check a.js
node --test tests/*.test.cjs tests/*.test.mjs
node tests/settings-smoke.cjs
node scripts/build-data.mjs --verify data/generated/v1
```

## Сценарий проверки на LG webOS

1. Удалить прежний плагин, установить `https://nmagic.github.io/lampa-anime-filler/a.js`, полностью перезапустить Lampa.
2. Открыть Bleach с TMDB ID `30984`, выбрать Online_Mod и дождаться загрузки списка до E366.
3. В диагностике проверить: версия `0.4.1`, сопоставление `TMDB ID`, `online_mod S1 E366`, пример `online_mod S1 E366 → 366`. `Номеров распознано` должно быть близко числу структурированных строк и больше прежних 7.
4. Визуально проверить E1 как canon, E33 и E64 как filler, E366 как canon. При наличии S2 проверить E1 → absolute 367; значения выше S2E42 не должны получать метку.
5. Повторить для BWA. Если payload содержит только season/episode, ожидается `bwa … → unknown` без ложных меток. Если BWA содержит `absolute_episode`, соответствующая метка допустима.
6. Сохранить фото обеих диагностик с полями `Пример сопоставления`, `Номеров распознано`, `Неизвестных соответствий`, `Меток проставлено`.

## Границы изменения

- Playback Controller не изменён.
- Автоматический пропуск, плейлист и запуск видео не изменены.
- Fuzzy title matching не добавлялся.
- DOM/template hook сохранён; в него добавлен только adapter id.
- BWA seasonal mapping намеренно не добавлен до получения достоверной диагностики его numbering system.
- Изменение ограничено data contract, build-time mapping, mapper, диагностикой, документацией и тестами.
